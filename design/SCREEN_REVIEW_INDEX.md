All editable routes distinguish Saving, Saved, Unsaved and Save failed. Approval actions wait for successful save. Conflicts preserve local input. One active generation per project; previous validated output stays available. Spoken changes return to storyboard approval; visual changes still require final video review. Schedules pin a specific video, caption and account. Uncertain external publish outcomes reconcile before retry. Generic unavailable screens never reveal another owner's data.

## Review and implementation boundary

Stitch screens are visual specifications. Buttons, providers, auth and persistence are not application implementations. Video thumbnails are illustrative unless connected to real prototype assets. Animation affordances are not evidence of generated video functionality. Accessibility, media playback, responsive behavior, validation, API integration and state transitions must be implemented and tested later.

Desktop primary routes are complemented by mobile adaptations of the main journey plus mobile sign-in/recovery (23), personal settings (24), Instagram connection (25), and schedule/recovery sheets (26). These are responsive variants, not additional application routes. Tablet reflows use the same layout rules. State panels capture unique copy/actions without multiplying equivalent full-page layouts.
